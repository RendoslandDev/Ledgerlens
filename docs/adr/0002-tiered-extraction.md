# ADR 0002: Tiered extraction and deterministic totals

- Status: Accepted
- Date: 2026-09-30

## Context

Running a large vision-language model for every page is costly, and plausible-looking financial
values still need verifiable arithmetic. Corrections also need to remain useful for evaluation.

## Decision

Use a cheap OCR/rules path first, validate the resulting fields, and reserve model escalation for
uncertain cases. Structured totals and spend questions are computed from validated SQLite records,
not generated by an LLM. Preserve user corrections as data and route uncertain documents to review.

## Consequences

The fast path is testable without model weights and can be benchmarked per field. Validation and
review policy are part of the product contract. Model escalation, correction history, and
production-quality evaluation are still being built.
