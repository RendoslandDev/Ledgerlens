# ADR 0003: Typed application boundary

- Status: Accepted
- Date: 2026-09-30

## Context

The desktop client is planned as a Tauri application with a React/TypeScript webview. Hand-maintained
request and response types would drift from Rust command signatures.

## Decision

Generate TypeScript command bindings from the Rust command layer with `tauri-specta`. Keep the
generated package in `packages/bindings`; do not hand-edit generated API declarations.

## Consequences

Rust remains authoritative for the IPC contract.

## Implementation (2026-10-27)

- `packages/bindings/src/bindings.ts` is generated by `tauri-specta` 2.0.0-rc.26 from the command
  layer; boundary types derive `specta::Type` behind an `ll-app`/`ll-core` `specta` feature, so
  crates outside the desktop shell do not depend on it.
- `npm --prefix apps/desktop run bindings` regenerates the file; a test in `src-tauri`
  (`bindings_are_current`) fails when it drifts, so `cargo test` catches a stale contract.
- Serde phases are disabled: every boundary type travels in one direction, so each has a single
  TypeScript shape. Closed sets (status, kind, field names, tiers) are exported as unions.
- 64-bit integers export as `number` only where a field opts in with `specta_typescript::Number`;
  amounts are capped at 2^53 - 1 minor units on entry.
- `commands_dispatch_through_ipc` (in `src-tauri`) drives both handlers through Tauri's IPC with
  the mock runtime and the app's real permission manifest, including a raw-bytes import, and
  checks that a request from a foreign origin is refused.
- Exception: `import_document` and `document_file` carry raw bytes and are dispatched outside
  `tauri-specta`; their names live in `packages/bindings/src/raw.ts` and their result type is
  still generated.
